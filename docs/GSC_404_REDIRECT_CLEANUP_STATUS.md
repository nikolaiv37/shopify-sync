# GSC 404 Redirect Cleanup — Status

Status document for the SEO migration redirect cleanup following the CloudCart → Shopify move.

## Context

MebelCenter migrated from CloudCart to Shopify (`mebelcenter.bg`, Shopify store `mebel-center.myshopify.com`). The old CloudCart URL structure — `/product/...`, `/category/...`, `/vendor/...`, `/selection/...`, `/article/...` — no longer resolves on Shopify and returns 404. Google Search Console is reporting these old, still-indexed URLs as 404s.

The old slugs are title-based (e.g. `/product/masa-rebel-megapap-cvyat-rota-dab-pyasachnik-150x90x75cm`), while current Shopify product handles are usually SKU-based (`/products/mc-XXXXX`). Old slug ≠ new handle, so redirects cannot be generated by naive slug rewriting — each redirect has to be matched and confidence-scored.

## GSC / Sitemap Status

- Google Search Console is verified and `sitemap.xml` submitted successfully.
- The Shopify sitemap (~10K indexed pages) is **healthy** — not the problem.
- The SEO issue is purely **old, known CloudCart URLs returning 404**, not sitemap coverage.

## Scripts Created

- `scripts/seo/audit-gsc-404-redirects.ts` — read-only audit. Parses the GSC 404 export, groups URLs by old route type, matches `/product/` paths to Shopify products and `/category/` paths to collections with confidence scoring, and writes `redirects-ready.csv`, `manual-review.csv`, `unmatched.csv`, `grouped-counts.csv`, `summary.json`. Includes an optional old-domain lookup mode (`--old-domain=vorno.bg`) that scrapes the still-live old CloudCart catalog, extracts JSON-LD `sku`/signals, and only promotes a match to "ready" when an extracted code resolves to exactly one current Shopify variant SKU.
- `scripts/seo/apply-gsc-404-redirects.ts` — applier. Dry-run by default; `--apply` required to write. Idempotent and non-destructive: never overwrites or deletes existing redirects.

npm scripts: `seo:gsc404:audit`, `seo:gsc404:apply:dry`, `seo:gsc404:apply`, `seo:gsc404:check-access`, `seo:gsc404:typecheck`.

## Shopify App / Scopes Finding

- The repo authenticates via the **client-credentials** flow (`SHOPIFY_CLIENT_ID` / `SHOPIFY_CLIENT_SECRET` in `.env`), exchanged for a fresh Admin API token each run.
- The `--check-access` diagnostic confirmed those credentials resolve to the **Supplier Sync** app on shop **Mebel Center** — not a separate dev app.
- URL redirects require the scopes **`read_online_store_navigation`** and **`write_online_store_navigation`** (surfaced as `read_url_redirects` / `write_url_redirects` in some Shopify versions). After the app was re-released with these scopes, `urlRedirects` queries and `urlRedirectCreate` mutations work.

## Category Audit

- 18 category redirect rows were marked "ready" by the audit.
- The category dry-run initially reported 18 **conflicts** — but these were **false conflicts**: Shopify stored the existing redirect targets as percent-encoded Cyrillic (`/collections/%D0%BF%D0%BE...`) while the audit CSV carried decoded Cyrillic (`/collections/помощни-маси`). They are the same URL.
- Fixed with a `normalizePath()` comparison in the apply script: target paths are decoded per-segment and Unicode-NFC normalized **for equality checks only**; the original target path is preserved when creating redirects.
- After the fix the dry-run reports all 18 as `skip_existing_same`, with **0 conflicts and 0 errors** — the category redirects already exist and need no action.

| vendor | 10 | 35 |

**Decision:**

- **vendor / selection** — no automatic redirects. The vendor 404s are mostly paginated listing pages (`?page=N`). Redirect manually only when an exact current equivalent (Shopify collection/vendor or page) exists; otherwise leave as 404.
- **article** — manually check each of the 2 article pages for a matching Shopify blog post and redirect only if a genuine equivalent exists.

## Important Warnings

- **Do not press "Validate Fix" in Google Search Console yet.** Many old URLs still have no redirect; validating now would fail.
- **Do not mass-redirect unmatched products to the homepage.** A homepage redirect for a missing product is a poor user and SEO outcome — unmatched rows must stay unmatched until a real target is found.
- **Only apply redirects after a dry-run shows zero conflicts and zero errors.** Apply runs must be gated on a clean dry-run.
